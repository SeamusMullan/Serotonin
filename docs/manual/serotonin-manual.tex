	\section{Hardware Support}

	\subsection{Minimum Requirements}

	The following specifications are required to run Serotonin:
	\begin{itemize}
		\item x86 CPU with Streaming SIMD Extensions 2 (SSE2) instruction set extension (Intel Pentium 4, AMD Athlon64, VIA C7 or newer)
		\item $\geq$1GiB of RAM
		\item Legacy BIOS with VESA BIOS Extensions 2.0 support
		\item $\geq$TBDGiB of hard disk space
	\end{itemize}

	\subsection{Video}
	Serotonin supports the VESA BIOS Extensions, preconfigured for a resolution of 1280x800 with 32-bit true colour (16,777,216 possible colours, excluding the alpha channel).

	\subsection{Audio}

	\subsubsection{PC Speaker}
	The PC Speaker is capable of generating basic square waves.

	\subsubsection{Yamaha YM3812 (OPL2)}
	The YM3812 is a sound integrated circuit, popularised by the AdLib and Sound Blaster sound cards. It is capable of 9 melodic voice polyphony (6 melodic + 5 percussion in rhythm mode). Each voice has 2 operators for Frequency Modulation (FM) and additive synthesis, 4 selectable waveforms per operator (sine, half sine, absolute sine, quarters ine) and per operator 4-bit ADSR (attack, decay, sustain, release).

\section{Compilation}
\subsection{Application Binary Interface}
Serotonin uses the System V ABI, this includes the calling convention and executable format (ELF). Therefore, it is recommended to use the GNU Compiler Collection (GCC) when compiling both the kernel and and usermode programs.

\subsection{GCC Cross Compilation}
You should use the i686-elf target for cross compiling from a different operating system other then Serotonin. This will be subject to change when an OS specific toolchain is completed at some point in the future.

\section{Kernel}
\subsection{Overview}
The Serotonin kernel is a higher-half, monolithic kernel with preemptive usermode scheduling, a virtual filesystem, and a global compositor. It uses a per-task address space, a buddy allocator for physical memory, and a syscall ABI via \texttt{int 0x80}.

\subsection{Memory Management}
Serotonin uses paging with a higher-half kernel layout. Key virtual address ranges are:
\begin{itemize}
	\item Kernel virtual base: \texttt{0xC0000000} (256 MiB mapped)
	\item Kernel heap: \texttt{0xD0000000} (256 MiB)
	\item Framebuffer: \texttt{0xE0000000}
	\item Layer window region: \texttt{0xE1000000} up to \texttt{0xF0000000}
	\item Kernel stack region: \texttt{0xF0000000} (4 MiB reserved)
\end{itemize}
User address space ranges:
\begin{itemize}
	\item User code/data: \texttt{0x00400000} - \texttt{0xBFFFFFFF}
	\item User heap: \texttt{0x20000000} - \texttt{0x5FFFFFFF}
	\item Shared memory: \texttt{0x60000000} - \texttt{0x9FFFFFFF}
	\item User stack: top at \texttt{0xBF000000}, size 1 MiB, grows downward
	\item Signal trampoline: \texttt{0xBFF00000}
\end{itemize}
Physical memory is managed by a buddy allocator with multiple zones, and per-process address spaces are switched on context switches.

\subsection{Process, Signals, and IPC}
Each task has a process control block (PCB) with register state, FPU state, file descriptor table, and scheduling metadata. The kernel supports:
\begin{itemize}
	\item Preemptive usermode and cooperative kernel mode scheduling
	\item Signal delivery with 16 signal types and per-process handlers
	\item Shared memory objects (create/map) in a dedicated virtual range
	\item Kernel locks and semaphores for synchronization
\end{itemize}

\subsection{Filesystems}
Serotonin provides a virtual filesystem (VFS) with pluggable filesystem drivers. Current drivers include FAT32 and TMPFS/RAMFS. Processes track a current working directory and operate on files using file descriptors backed by VFS nodes.

\subsection{Device and Timekeeping}
The kernel includes drivers for PIT-based time slicing, RTC time-of-day, PS/2 keyboard and mouse, serial output, legacy IDE storage, VBE graphics, and basic audio output (PC speaker and OPL2).

\section{The Serotonin Scheduler}

\subsection{Brief Overview}
The Serotonin Scheduler is a priority round-robin scheduler for kernel mode (Ring 0, "Supervisor mode") and user mode processes (Ring 3). Kernel mode tasks are cooperative (that is, you must explicity yield or block in your code), and usermode tasks are preemptive (the scheduler will preempt your process on the PIT timer). The time quantum is 10ms (\texttt{SCHEDULE\_QUANTUM}) and priority decay is applied after consuming quanta. There are 256 possible priorities, 0 being the lowest (idle task) and 255 the highest (/bin/init). The scheduler always picks the highest priority task that is ready to run; tasks of equal priority are scheduled round-robin.

\subsection{Process entry point}
You must provide the entry point of the process. The scheduler will then start execution from the provided pointer, provided that the process is in the scheduler queue, the process is ready and is not blocked. Kernel mode code runs in the higher-half mapping at \texttt{0xC0000000}+; user mode binaries are expected to load into user space (\texttt{0x00400000} - \texttt{0xBFFFFFFF}).

\subsection{Process stack}
The scheduler will allocate a stack for you, the size and location depends on the privilege level. Kernel mode stacks are 16 KiB each, allocated from the top of the \texttt{0xF0000000} - \texttt{0xF03FFFFF} region and grow downward. User mode stacks are 1 MiB each, allocated from \texttt{0xBF000000} downward and grow downward.

	\subsection{Creating a kernel mode process}
	You can create a new kernel mode process by creating a process and adding it to the scheduler queue:
	\begin{lstlisting}[language=C]
#include "stdio/stdio.h"
#include "schedule/schedule.h"

void my_process(void)
{
	for (int i = 0; i < 5; i++) {
		printf("Hello, kernel world!\n");
		kernel_yield();
	}
	task_exit(get_current_task(), EXIT_SIGTERM);
}

// kernel_main_high
process_control_block_t *my_pcb = task_create(my_process, "my_process", CPU_KERNEL_MODE, 128);
enqueue(my_pcb);
	\end{lstlisting}
	Note that you have to yield the CPU after you are done with your computation. This is important so that other processes can have CPU time and are not starved. Failing to yield the CPU can result in lockups/freezes, and this is not ideal for the end user experience.

	\subsection{Creating a user mode process from kernel mode}
	While in most cases, this is not required, as you should be creating usermode tasks from usermode, it is possible to do so by loading an ELF binary.
	\begin{lstlisting}
# /bin/myusermodetask
.section .rodata
msg: .asciz "Hello, world!\n"

.section .text
.global _start
_start:
	movl $1,   %eax # WRITE
	movl $0,   %ebx # STDOUT
	movl $msg, %ecx # pointer to message
	movl $14,  %edx # length
	int  $0x80      # send syscall to kernel

	movl $0,   %eax # EXIT
	movl $15,  %ebx # SIGTERM
	int $0x80       # send syscall to kernel

	\end{lstlisting}
	\begin{lstlisting}[language=C]
#include "stdio/stdio.h"
#include "schedule/schedule.h"
#include "kernel.h"

// kernel_main_high
char* elf_loc = "/bin/mytask";
process_control_block_t *init = task_create(NULL, elf_loc, CPU_USER_MODE, 128);
const char *argv[1] = {"/bin/mytask"}; int argc = 1;
const char *envp[1] = {"PATH=/"}; int envc = 1;
int init_status = kernel_load_elf(init, elf_loc, elf_loc, argv, argc, envp, envc);
kernel_yield();
	\end{lstlisting}
	The \texttt{kernel\_load\_elf} function will automatically enqueue the task into the scheduler. You can now yield from the current kernel task. Notice how there is no "yield" in the usermode task. This is because all usermode tasks are preempted by the kernel. You can read more about the Serotonin system call interface in the "System Call Interface" chapter.

	\subsection{Creating a user mode process from user mode}
	You can create a new user mode process by using the fork and execve system calls. More detail can be viewed in the "System Call Interface" chapter.
	\begin{lstlisting}
.section .text
.global _start
_start:
	movl $4,   %eax # FORK
	int  $0x80      # send syscall to kernel

	cmpl $0,   %eax
	je   child      # eax==0 if child
	jg   parent     # eax==child_pid if parent (eax>0)

	jmp  error      # eax<0 if fork failed

child:
        # do whatever in child

parent:
	# do whatever in parent

error:
	# handle error

	\end{lstlisting}

\section{System Call Interface}
\subsection{Brief Overview}
Serotonin uses the interrupt 0x80 to handle system calls generated by usermode tasks, and arguments are taken from the general purpose registers eax, ebx, ecx and edx. The eax register is used to specify the system call operation, while ebx, ecx and edx are used as arguments for the system call. For example, the exit system call uses eax=0, and ebx is used to specify the exit code.

\subsection{Error Handling}
System calls return their result in eax. On failure, the kernel returns a negative errno value in eax. User-space wrappers translate this into \texttt{errno}.

\subsection{System Call List}
\subsubsection{Process and memory}
\begin{itemize}
	\item \texttt{0 EXIT} (ebx=status) terminate the current process.
	\item \texttt{3 EXECVE} (ebx=path, ecx=argv, edx=envp) replace the current process image.
	\item \texttt{4 FORK} duplicate the current process.
	\item \texttt{5 GETPID} return the current process ID.
	\item \texttt{9 WAITPID} (ebx=pid, ecx=status*) wait on a child.

	\item \texttt{17 KILL} (ebx=pid, ecx=sig) send a signal.
	\item \texttt{18 SIGNAL} (ebx=sig, ecx=handler) register a signal handler.
	\item \texttt{19 SIGRET} return from a signal handler.
	\item \texttt{25 PAUSE} block until a signal is received.
	\item \texttt{26 SHM\_CREATE} (ebx=size) create a shared memory object.
	\item \texttt{27 SHM\_MAP} (ebx=shm\_id) map a shared memory object.
	\item \texttt{28 SHM\_UNMAP} (ebx=addr) unmap a shared memory object (currently returns \texttt{ENOSYS}).

	\item \texttt{6 TTY} (ebx=fd) test if a file descriptor is a TTY.
	\item \texttt{7 OPEN} (ebx=path, ecx=flags) open a file.

    \section{Kernel Compositor}
    \subsection{Brief Overview}
    The Serotonin kernel provides a global compositor for all tasks, kernel and user. The compositor manages 16 z layers and supports alpha blending for all layers except the base layer (layer zero). User tasks can allocate and configure layers through the 5HT system calls, writing pixel data into shared layer buffers and signaling frame completion through layer metadata.

    \section{Usermode C Library}
	Serotonin user programs use a newlib-based C library with syscall wrappers for kernel services. Startup is provided by \texttt{crt0.o}, and the syscall glue in \texttt{user/syscall/syscall.c} exposes POSIX-like APIs (stdio, file I/O, process control, signals, and basic filesystem operations). Memory allocation uses \texttt{sbrk} backed by the kernel user heap. The library is intentionally small and does not provide full POSIX coverage yet.

    \section{Usermode C++ Library}
	Serotonin provides a minimal C++ runtime and STL support for userland. The runtime supplies global constructor/destructor handling (\texttt{cxx\_init.o}), \texttt{\_\_cxa\_atexit}/\texttt{\_\_cxa\_finalize}, \texttt{\_\_cxa\_pure\_virtual}, and \texttt{new}/\texttt{delete} operators. The standard library uses STLport 5.2.1 with stubs for exception-related throws; builds are configured without C++ exceptions and error paths abort instead of throwing. iostream and basic STL containers are supported, but higher-level facilities may be incomplete.

    \subsubsection{Tiling Window Manager - Ionic}

	Serotonin implements a tiling window manager (WM) called Ionic, named after Ionic bonds.
	The WM is a simplistic, low fidelity UI made purely for performance.
	This is advised for lower end hardware nearer to the Hardware Requirements spec.
	Windows are organised in a grid-like structure.
	This WM is enabled by default in the settings.

	Ionic features 2-dimensional workspaces, meaning users can have multiple virtual desktops arranged both horizontally and vertically, categorized with numbers and letters.

    \subsubsection{Floating / Stacking Window Manager - Covalence}

    Covalence is a floating WM implemented into Serotonin as an alternative to Ionic. Covalence is much more intuitive for end users familiar with operating systems like MacOS, Windows and other WMs like Gnome or KDE. Named after covalence bonds, this window manager allows users to move, resize, minimize and close windows with their mouse, or optionally with keyboard shortcuts. Naturally this WM is more computationally expensive and must be enabled manually by the user.

    \subsection{Running Programs}

    \subsubsection{Quick Run}

    Processes can be opened using the default shortcut \lstinline{MOD + D} which opens the program selection dialog, [insert name here]. The user can then open a previous task using \lstinline{CTRL + NUM}, where \lstinline{NUM} is a number key from 1 to 3.

    \subsubsection{Searching Programs}

    The user can also begin to type the name of a program to search the system for it instead. The program is then run by pressing \lstinline{ENTER}. The arrow keys or tab can be used to cycle through the current options, as well as double clicking the program in the list.

    \subsection{Settings}

    Serotonin allows users to customize their desktop experience inside the settings program. Users can change their wallpaper, taskbar colour and location, default window manager and other settings as they get implemented. The menu will render using an Ionic-style window so low end hardware can always run the settings app. This guarantees they can configure their system to perform well.
